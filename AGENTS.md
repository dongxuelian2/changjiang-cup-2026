# Research principles

- Work on mathematical and algorithmic questions that improve competitive experimental candidates. Engineering serves the research.
- Record useful conclusions promptly in `MATH.md`; separate proved statements, finite experiments, and unverified biological or statistical assumptions.
- Keep assumptions and the precise objective next to each result. Synthetic scenario weights are modelling choices, not measured success probabilities.
- Preserve original model scores, units, versions, and meanings. Calibrate against relevant experimental evidence before interpreting or combining them as biological utilities.
- Keep code, experiments, and documentation small. Use CPU experiments for this stage; add model infrastructure only for a concrete research need.
- Keep generated outputs in ignored `build/`. Retain source, small necessary examples, and concise numerical findings; avoid logs, certificates, CI, and duplicate research reports.
- README describes implemented capabilities and actual results. `RULES.md` records verified official information and unresolved publication/access questions.
- Change research direction freely when official briefs, model outputs, or experiments justify it. Do not design against an unconfirmed target.
- Run relevant correctness checks, then commit and push authorized work. Preserve shared Git history; do not force push.
